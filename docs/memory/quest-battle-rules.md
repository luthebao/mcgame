# Quest Battle, Tracker, and Accept-Time Handoff Rules

Quest-battle NPCs now stay on the NPC `clickNpc` path instead of relying on the combat handler registration. Type `20` NPCs resolve an active matching quest from their `subType` list and start a normal `onBattleStart` PVE battle from the first unfinished kill objective, which lets quest `50` NPC `475` spawn creature `157` (`Kê Vương`). The NPC battle-start helper must also register the initiating connection as a battle watcher, otherwise the round resolves server-side but `onBattlePlayList` never reaches the client after target selection. Quest kill credit must be collected from the battle participants even when the round processor has already ended and cached the battle before `battlePlayEnd`, or quest-battle boss kills will not flip the quest to finishable state.

Active kill-quest DTOs must not leave `pos.name` as the navigation map label when a monster objective exists. The Flash quest UI prefers `pos.name` over `require[*].creature.name`, so `EnrichQuestDTO()` now rewrites `pos.name` to the first kill target creature name while keeping the NPC/map coordinates for navigation; this fixes quests like `3165` showing the wrong boss in the tracker.

Quest boss starters are not limited to NPC type `20`. Some challenge NPCs, including quest `3165` on NPC `143`, are `NPCTypeBattle` (`type = 10`) with quest-id lists in `subType`; `clickNpc` must route both `type 20` and `type 10` through the quest-battle starter when an active matching kill quest exists, otherwise the client only opens normal NPC interaction and the boss fight never starts. That quest-battle resolver must stop once the stored kill objective is already complete: only fall back to `TBL_QUEST_REQUIRE` when the active progress has no kill objective data yet, or the turn-in click will incorrectly reopen the boss fight instead of letting the player finish the quest.

Quest accept-time handoff items now go through a shared handler helper for both `takeQuest` and `takeBuildQuest` instead of a one-off quest-160 branch. The current allowlist grants quest-bag items `335` for quest `160`, `515` for quest `162`, and `517` for quest `164`, while preserving the existing `onAddItem` and `onAddCharactorSlot` callbacks so Flash `q=-1` quest-item requirements become immediately obtainable.

## Quest-Battle Boss Encounter Level (MinLevel / 2)

Quest-battle bosses are sized from `quest.MinLevel / 2`, not `creature.use_lv`. `quest_battle.go` returns the matched `questID` from `resolveQuestBattleCreatureIDs` and feeds `questEncounterLevel(questID) = max(1, MinLevel/2)` into a new combat service method `combat.Service.BuildCreatureTemplateAtLevel(ctx, charID, creatureID, level)`. The new method mirrors `BuildCreatureTemplateForCharacter` but skips the `MapCreature → use_lv → mapLevel` fallback ladder, taking the level argument directly into `CalculateCreatureStats`. If `MinLevel` is unset (zero), `questEncounterLevel` returns 0 and the call site falls back to the old `BuildCreatureTemplateForCharacter` path so no quest is left without enemies.

The level enters the HP formula in two places: the cubic level multiplier `level³/1000` in `stats.CreatureHPLevelMultiplier` (`internal/domain/stats/profile.go`), and as the `template.Level` denominator inside `NormalizeEncounterTemplateForPlayer` (`internal/application/combat/npc_stats.go`). Because `level = MinLevel/2` is always well below `playerLevel + 5` for any eligible quest-taker, the normalize step becomes a no-op — boss HP is **flat across player levels** for quest-battle encounters.

Worked example: quest `645` "Thăng Cấp Trung Cấp 3-2" has `MinLevel=40`, so encounter level = 20. The six Khảo Quan bosses (cids 92/94/96/99/216/330) drop from ~358k–1.2M HP (under the old `use_lv=120/200` path at player Lv 40) to ~4.4k–7.8k HP. The cubic level term dominates: `20³/1000 = 8` vs `120³/1000 = 1728` and `200³/1000 = 8000`, which is why the formerly-stronger `use_lv=200` bosses normalize closer to their `use_lv=120` peers under the new rule.

The rule applies to **every** quest-battle NPC click in `tryHandleQuestBattleNPCClick`, not just quest 645 — any quest using `NPCTypeQuestBattle`, `NPCTypeBattle`, or `NPCTypeStoryBattle` is sized this way. Changing the divisor (currently `/2`) or the floor (currently `1`) only requires editing `questEncounterLevel` in `internal/presentation/rtmp/handlers/npc/quest_battle.go`.
